# MCP SafeTripwire 设计文档

## 1. 定位

做一个**透明的、不依赖 LLM 的 MCP 安全 broker**：让普通人在自己机器上、
数据不出门、免费地，把 MCP 的权限关进笼子。

- 不追求"识别所有恶意 MCP"——那是语义问题，纯程序有漏报下限。
- 追求"强制最小权限 + 完整性 + 数据流管控"——结构问题，纯程序可靠。
- 静态扫描与风险分类是**证据与上下文**，不是主防线。主防线是**权限不允许它成功**。

## 2. 为什么通用（Win + Mac + 所有 Agent + 所有传输）

MCP 规范定义两种标准传输（另允许自定义），它们的**配置形态不同，拦截方式也不同**：

```
stdio   : 宿主 --stdio--> [ mcp-safetripwire wrap ] --stdio--> 真实子进程
          （宿主启动的那一行被改写；不需要任何特权）

HTTP    : 宿主 --http--> http://127.0.0.1:8788/<name>/... --http--> https://real/mcp
          （url 被改写为本地；由 `serve` 起的反代转发。含 Streamable HTTP 与旧版 SSE）
```

- stdio：宿主配置里把"启动真实服务器"换成"启动 Tripwire"。
  纯进程 + 管道 I/O，Windows 与 macOS 行为一致，**不需要任何系统特权**。
- HTTP：远程服务器没有可包裹的子进程，只能把 `url` 指向本地反代。
  旧版 HTTP+SSE 还要把 SSE 首个 `endpoint` 事件重写回本地，否则客户端会绕过代理直连。
- **两种传输共用同一个决策内核**（`inspect.js`）。传输只搬字节，判定必须一致——
  否则同一个服务器换个传输就可能绕过。这是"covers all"成立的技术根据。
- 自定义传输：决策内核已与传输解耦，新增适配器即可接入。

## 3. 分层架构

```
宿主
 │  强制所有 MCP 流量经过：stdio 包住子进程 / HTTP 改写 url 到本地
 ▼
[ mcp-safetripwire ]
 ├─ 传输层    proxy.js（stdio）  ·  httpproxy.js（Streamable HTTP / 旧版 SSE）
 ├─ 决策内核  inspect.js —— 所有传输共用，保证判定一致
 │     ├─ 完整性层  manifest 哈希固定，工具面变更即拦截（TOFU / lockfile 思路）
 │     ├─ 静态层    元数据扫描：不可见字符、指令式语言、跨工具引用、编码块
 │     ├─ 风险层    能力分类：code-execution / credential-access / network-egress / fs-*
 │     └─ 策略层    三档强制姿态（warn/strip/block）+ 白/黑名单 + **先审后用（未批准通道默认拒绝）**
 ├─ 管理层    console.js（本地网页控制台）· menu.js（终端菜单）· 桌面快捷方式 · 开机自启
 ├─ 运行时层  （P3）原生沙箱：文件 / 网络 / 执行拦截
 └─ 诱捕层    （P2）诱饵 server、诱饵工具、honeytoken
 │
 ▼
MCP servers（一律不可信）
```

观测点全部在 Tripwire 侧，不在服务器进程内——被攻陷的服务器会蒙蔽自身内部的一切。

## 4. 威胁模型 / 检测矩阵

| 攻击手法 | 纯程序可做性 | Tripwire 机制 | 状态 |
|---|---|---|---|
| Tool poisoning（描述里藏指令） | 结构层可检测 | 静态扫描（Tag 块/零宽/bidi/编码块/指令式语言）+ `strip`/`block` | ✅ |
| Rug pull（审批后偷换工具面） | **可靠** | 哈希固定，变更即告警/拦截 | ✅ |
| 危险能力被滥用（如任意代码执行） | **可靠** | 风险分类 + `denyTools` 策略 | ✅ |
| 工具重名 / 影子 | 可靠 | 命名空间隔离 + homoglyph 相似度 | ⏳ P1 |
| 跨服务器信任转移 | 部分 | 跨工具引用扫描；污点追踪在 P4 | 🟡 部分 |
| 凭据 / token 窃取 | 可靠 | 原生沙箱 + canary 凭据 | ⏳ P3 |
| 供应链（typosquat / 安装脚本） | 可靠 | 安装前静态扫描 + 沙箱化动态安装 | ⏳ P2 |
| 工具输出里的间接注入 | 结构层部分 | 输出通道字符/编码扫描 | ⏳ P2 |
| 过量授权 | 可靠 | 声明能力 vs 实际调用比对 | 🟡 部分 |

**默认拒绝**：`protect` 姿态下，未被批准过的通道（无 pin）其 `tools/call` 一律拒绝（`unreviewed`）。
批准来自"观测"而非"重跑"：代理在 `tools/list` 上记录实际观测到的工具面为 pending，人工在控制台批准后
提升为 pin。这样"审的就是线上那一个"，不存在审的和跑的不是同一个的问题。

**纯程序无解的**：一段语法完全正常、无任何结构异常的自然语言注入。
对这种唯一有效的手段是**权限根本不允许它成功**。

## 5. "信任转移危机" = 信息流控制问题

链条：用户信任宿主 → 宿主信任模型 → 模型被不可信内容影响 →
不可信内容经工具调用回流到敏感操作。每一跳都没有标签，信任被无声转移。

对应三件机制（传统安全成熟技术，搬到 MCP 传输层）：

- **能力（capability）**：每个 server 一张显式能力表——能碰哪些路径、能出哪些网、能否 exec。
- **污点（taint）**：来自不可信源（resource、工具输出）的字节打标，追踪是否流向敏感汇。
- **边界**：跨 server 的上下文默认不互通，要通必须策略显式放行。

Tripwire 现在落地的是 capability 的一半（风险分类 + 策略）。

## 6. 关键设计决策

1. **不做意图识别**：语义判断交给人类与策略，程序只做结构强制。
2. **默认 warn 而非 block**：误报阻断正常调用 = 用户当天卸载。硬阻断是显式选择。
3. **段级、可回滚的配置改写**：只动目标 server 的 command/args；TOML 走有界解析，
   写后重新解析校验，失败自动还原备份。宁可让用户手贴片段，也不猜坏配置。
4. **enforcement 抽成纯函数**（`evaluate.js`）：给定工具面/固定哈希/姿态算出唯一动作，
   可单测、可推理，不依赖进程。
5. **stdout 神圣**：JSON-RPC 占 stdout，人类输出走 stderr，审计写 JSONL 文件。

## 7. 跨平台要点

| 层 | Windows | macOS | 备注 |
|---|---|---|---|
| 代理层（现在） | Node 18+ | Node 18+ | 零特权，行为一致 |
| 原生沙箱（P3） | Job Objects、受限令牌/AppContainer、WFP 网络过滤、minifilter（需签名驱动） | `sandbox_init` seatbelt、EndpointSecurity（需 entitlement + Apple 审核）、Network Extension | 需特权与签名，故后置 |
| 分发 | winget / scoop / 直下 | Homebrew / 直下；**必须 codesign + notarize** | 后阶段可用 `bun build --compile` / Node SEA 打成单文件 |

关键判断：**先做不需要特权的那一层**（代理），赢得信任后再加需要特权的强制执行。
这也是它能先分发给普通人的原因。

## 8. 路线图

- **P0 ✅** 两种传输的透明拦截（stdio `wrap` + HTTP/SSE `serve`）+ 共享决策内核
  + 审计 + 静态扫描 + 哈希固定 + 三档强制 + 风险分类
- **P1 ✅（部分）** 宿主配置定位与段级改写（Codex/Claude/Cursor；stdio 与 url 两种形态）
  + 图形控制台（本地网页 UI，token + Host/Origin 校验）+ 桌面入口 + 开机自启
  - 余项：工具重名/影子检测、rug-pull 差异对比视图、策略包
- **P2** **自定义传输适配器**（首个目标：Blender MCP 的 `localhost:9876` 裸 TCP +
  空字节分隔 JSON，协议 `{"type":"execute","code":…}`；提供官方自认缺失的策略与审计）
  ；诱饵 server + honeytoken；输出通道扫描；供应链扫描；HTTP 路径实机联调
  ；托盘常驻与原生通知
- **P3** 原生沙箱旁路（Rust）：文件 / 网络 / 执行强制
- **P4** 工具输出的污点追踪；MITRE ATLAS / ATT&CK 覆盖映射
- **P5** 打包与签名公证（单文件分发）；插件市场形态

## 9. 已知限制（诚实清单）

1. **服务器进程尚未沙箱化**（P3 之前）——能拦工具调用层，拦不住进程直接读文件/外联。
2. **只看走 MCP 传输的流量**（stdio 或 HTTP）。服务器自身另开的上游通道是盲区，
   例如 Blender MCP 的 addon 与 Blender 之间的本地 socket。
3. **HTTP 路径未实机联调**——路由解析与 SSE 分帧有单测，端到端仍待真实服务器验证。
4. **自定义传输完全未覆盖**。已确认的实例：Blender MCP 扩展用 `localhost:9876` 的裸 TCP +
   空字节分隔 JSON，协议是 `{"type":"execute","code":…}`，即**协议本身就是任意代码执行**——
   对它而言"工具投毒"不是威胁模型，"谁能连上这个端口"才是。该适配器是 P2 的首要项。
5. **控制台的安全边界**是"本机 + token"。任何能以你身份在本机跑的进程都能读 token；
   控制台不是提权边界，它保护的是"别的网页/别的机器不能驱动它"。
6. **语义注入有漏报下限**——靠权限兜底。
7. **跨 server 污点经 LLM 上下文会变模糊**——工具输出是自然语言，字节级追踪断裂，
   只能退化为时序关联，准确率打折。全系统最难的一块。
8. **风险分类是词法的**——会误报、会漏报，只作上下文，不作判决。
9. **代理层会重新序列化 JSON**——键序可能变化，语义不变；HTTP 下响应会重新分帧。
10. **阻断误报会砸生产力**——默认 warn。

## 10. 与"上架插件市场"的关系

MCP 插件市场列的是 **server**，Tripwire 是 **中间件**，不会作为普通 server 干净嵌入。
可行路径：先以独立程序分发（npm / Homebrew / winget），
之后要么让厂商推荐/内置，要么对外暴露一个薄的 "gateway" server 形态。
把形态押在市场插件上会很脆，独立程序先行。
